## [Unreleased]

### Added

- **Singleton grouping can no longer override a good classification, and the `setup-context` questionnaire now captures document HISTORY (run-12).** Two changes:

  **(Grouping guard):** the per-file (singleton) grouping step may now only **confirm or deepen the file's OWN analysis route** — to unite it with an existing series/affair AT or UNDER it — never relocate it to a sibling or a different subject. The deepen check compares the proposed path against the file's own `route_dir` (it must be a prefix of the proposal: equal = confirm + pull existing files down; longer = deepen), instead of against any resolved candidate branch. This stops the grouping from undoing the analysis's choice (run 12: a conservatory event classified `Hobbies/Musique` was being refiled `Hobbies/Fougeres`; a press clipping `Hobbies/Musique` was being moved to `Hobbies/Photo`) and from reforming magnets. Series uniting (the two meter readings) is unchanged. `tests/test_organize_pipeline.py` +1 (a sibling-subject relocation is ignored, the file stays put).

  **(Questionnaire captures history):** a filing tool handles OLD documents, so `setup-context` is reworked around **multi-value fields, current AND past** — professions, employers, own activities, the names that mean your work, banks, insurers, energy/water and telecom providers, housing, vehicles, household members — each entered as a comma-separated list with an explicit instruction (the previous single-status / radio questions assumed one current state, and comma-splitting wasn't obvious). The rendered context says "current or past" so the AI recognises a document from a former employer or provider. `tests/test_user_context_setup.py` reworked (multi-value parsing, history rendering). 313 tests green.

- **A guided `setup-context` questionnaire builds the user-context file, and the prompts use that context to file Hobbies by subject and to route work — as a GUIDE, never a constraint.** Three coupled changes (run-11 direction):

  **(`setup-context` command):** a short, UNIVERSAL questionnaire (works for an employee, self-employed, student, retiree, parent…) — identity + online aliases, work status with branching questions (employer / business / the names that mean *your* work), interests (a checklist + free text), an optional household section, free notes — that renders the answers to the plain-text context file `load_user_context` already reads. The user never hand-edits a config format; every question is skippable; the work questions branch on the declared status; a recap is shown before saving; and it warns if a higher-priority context file would shadow the one it writes. Answers are personal data (gitignored, never committed). New `procrafiler.user_context_setup` (`collect_answers` / `render_context` / `setup_context`, I/O injected for testing) + `user_context.active_context_path()` / `default_context_write_path()`; CLI `setup-context`.

  **(Hobbies filed by SUBJECT — B):** the analysis prompt now leads with a SUBJECT subfolder under a broad personal base (`…/Hobbies/Musique`, `…/Hobbies/Jardinage`), inferred from the document's CONTENT — so an audio-gear manual AND a music event both land under `Hobbies/Musique`, instead of the event being nested in the equipment folder (the run-8→11 "magnet"). The user's declared interests are a **guide** for naming/consistency, NOT a closed list: a hobby they didn't declare still gets its own subject folder.

  **(Work routing as a guide — D):** when the context lists names that mean the user's work (employer, business, clients, projects, tools), a related document leans Work — but the user's work is **not limited to that list**: clearly professional content is Work even when its name isn't listed (a user can't enumerate every project, and new ones appear). Applied in the analysis and organize prompts.

  This keeps the core principle intact: **the context disambiguates, the document's content decides.** `tests/test_user_context_setup.py` (new — branching, render, save/cancel), prompt assertions in `tests/test_ai_analysis.py` / `tests/test_ai_organize.py`, README command + note. 313 tests green.

- **AI sampling (temperature / top_p) is now neutral by default and configurable, instead of hardcoded `temperature=0.0`.** All three Mistral chat calls (analysis, organize, grouping) previously forced `temperature=0.0` — a hardcoded value never agreed and not obviously right for a mid-size model doing nuanced classification. They no longer pass it: by default **nothing is sent**, so Mistral applies its own (neutral) default — the reference baseline for tuning. Two new env vars let you override globally without code changes: `PROCRAFILER_AI_TEMPERATURE` and `PROCRAFILER_AI_TOP_P` (any float; an unparseable value is ignored; an explicit call-site param still wins). New `ai_naming._ai_sampling_params()`, applied inside `call_mistral_chat`. `tests/test_ai_providers.py` +5 (env parsing; the payload omits sampling by default and carries it when set). This unblocks comparing a neutral run vs `0.0` / `0.3` on the same inputs to see how much of the misplacement seen in runs 8–10 is sampling-driven. 304 tests green. *(Ollama is unchanged — it already sends no temperature, so it runs at its own default.)*

- **Certificates/diplomas are filed as a dated series, and a shared folder is named for its files' common subject — never after one item's brand (run-9 polish).** The ninth real sandbox run validated the run-8 fixes (empty Queue; `.srt`/`.sh` read & classified; `Utilities/Enercoop/2019` and `Utilities/EDF/2026` separate; `Banking/BNP-Paribas/2026`, `Telecom/Free-Mobile/2025`). Two prompt refinements:

  **(Certificates are a series):** the SERIES RULE kinds list now includes *certificate/attestation/diploma*, so a diploma files under its organism + year (e.g. `Education/OpenClassrooms/2023/`) instead of piling flat in the organism folder.

  **(Shared folders named by common subject):** the grouping wrongly created a folder named after one item's brand and pulled a different brand into it (a Soundcraft mixer manual landed in `Hobbies/SWR/`, named after the Blonde-II amp's brand). The grouping prompt now states the generalist rule: **name a shared folder by what its files have IN COMMON, never after one file's brand/model/title** — a folder named after a single entity is correct only when EVERY file in it is from that same entity (e.g. one issuer's bills); same-kind/different-brand items get a generic folder (e.g. `Materiel-audio`), never one brand. *(The grouping/organize calls already run at `temperature=0.0`, so this is a prompt-judgment fix, not a sampling one.)*

  `tests/test_ai_analysis.py` and `tests/test_ai_grouping.py` updated (prompt-intent assertions). 299 tests green.

- **Unsupported files go to Manual_Review instead of being stranded in the Queue, `.srt`/`.sh` are now read as text, different-issuer bills never share a folder, and unrelated items aren't nested under each other (run-8 fixes).** The eighth real sandbox run surfaced three problems:

  **(Bug 1 — files stuck in the Queue):** a file with an unsupported/missing extension was catalogued *at its Queue path* with status `USER_CONFIRMATION_REQUIRED` and **never moved** — it stayed physically in `Queue/`, invisible to `review` (which only surfaces `DECISION_PENDING`) and skipped by the next run (which iterates the Inbox, not the Queue) → stranded for good. Now an undispatchable file becomes a no-analysis `_CatalogedDoc` that the file phase places in **Manual_Review** (the catch-all for unreadable/unsupported content, status `LIBRARY_STORED`), exactly like an AI-unreadable file. The Queue is transient again (empty after a run). Separately, **`.srt` and `.sh` are added to the `text` media type** — they are plain text, so they are now read and classified normally instead of going to manual review. `tests/test_pipeline.py` and `tests/test_state_machine.py` updated (Manual_Review, not Queue); `tests/test_organize_pipeline.py` +1 (`.srt` read & classified).

  **(Bug 2 — an Enercoop bill was re-absorbed into `Utilities/EDF`):** the AI under-routed both bills to the bare base `Utilities` (the "if unsure, return just the base" escape conflicted with the series rule), so they sat loose together and the grouping merged them under one issuer. The fix is AI-first with a deterministic safety net: the analysis prompt now **requires** the entity folder for a series (never the bare base) and to reuse an existing folder only for the **same issuer**; and when the AI still stops at the base, `pipeline._with_series_entity` appends the issuer (from the analysis/catalog `entities.issuer`) as the entity folder — reusing an existing sibling case-insensitively — so two issuers can never share a base folder (`Utilities/Enercoop/2019`, `Utilities/EDF/2026`). `tests/test_series_year.py` +5, `tests/test_organize_pipeline.py` +1.

  **(Bug 3 — unrelated Hobbies items nested under one another):** a sound-mixer guide and a guitar-amp manual were pulled into `Hobbies/Codev-Express/` (a co-development workshop) just because all three sit under Hobbies. The analysis and grouping prompts now require a **SAME SPECIFIC subject** to reuse/nest a folder — items that merely share a broad parent category stay separate siblings, never nested one inside the other. `tests/test_ai_analysis.py` +1, `tests/test_ai_grouping.py` +1.

  298 tests green.

- **The series year subfolder is now derived deterministically by the code (from the document's own date), `Energy` becomes `Utilities`, and CVs are dated (run-7 fixes).** Run 7 validated the run-6 fixes but exposed that the **year subfolder was dropped** whenever a series folder was created or confirmed by the grouping/organize step (not by pure per-file classification): water-meter readings, OpenClassrooms certificates and the CAF bill all landed in their entity folder *without* a year, and the model had even *guessed the wrong year* (`2026` for readings dated 2024/2025). Root cause: the year was **model-written**. Now it is **code-owned**:

  **(Deterministic year):** the analysis returns a `series` boolean and proposes only the **ENTITY folder, without a year** (e.g. `…/Utilities/EDF`, `…/Banking/BNP-Paribas`, `…/Employment/CV`); the analysis, organize and grouping prompts all drop the year examples. The pipeline appends `/<YYYY>` **once** (`pipeline._with_series_year`), after grouping/organize have chosen the entity folder — the year from the document's **own** date (`document_dt` = EXIF/content date, never the processing timestamp) for a freshly filed file, and from the catalog fiche (`_fiche_year`) for an existing file a regroup pulls into a series. It is a no-op when the document is not a series, when the route is a bare base (no entity folder to date — e.g. a certificate the AI under-routed flat into `Education`), or when a year segment is already present. `series` is stored in the fiche. New `taxonomy.base_category_for` (longest base that prefixes a path) backs the "is there an entity folder below the base?" test.

  **(`Energy` → `Utilities`):** the base folder is renamed to the broader umbrella for metered home services — electricity, gas **and water** (a water-meter reading is not "energy"). `Telecom` stays separate. `taxonomy.BASE_LIBRARY_DIRECTORIES`, README and `docs/spec-mvp-v1.md` §10 trees updated; `tests/test_config_layout.py` repointed.

  **(CVs are dated):** a CV is now treated as a dated series (`series: true`, entity folder `…/Employment/CV`), so it files into `…/Employment/CV/<year>/` with the person's name kept in the **file** (`CV_LOUVEL-Simon`) — making the year of an old CV visible at a glance.

  `tests/test_series_year.py` (new — `base_category_for`, `_with_series_year`, `_fiche_year`), `tests/test_organize_pipeline.py` +3 (series file dated from its document date not the processing time, non-series not dated, series flat in a base not dated), `tests/test_ai_analysis.py` +1 and updated (series flag parsed; entity-only prompt), `tests/test_ai_organize.py` / `tests/test_ai_grouping.py` updated (entity-only, the system dates it). 288 tests green.

- **Series are now filed as `<Entity>/<Year>/`, a redundant leading date is stripped from names, a new file joining a series is named like its siblings, and bills of different suppliers never share a folder (run-6 refinements).** Four fixes from the sixth real sandbox run:

  **(Series = `<ENTITY>/<YEAR>/`):** a recurring kind (bill, statement, meter reading, payslip, tax notice…) is filed under a folder named after its **entity** — the issuer/organism (e.g. `Energy/EDF`, `Energy/Enercoop`, `Banking/BNP-Paribas`) or, lacking an issuer, the kind itself (`Housing/Releves-eau`) — with a **bare-year subfolder** for the document's year (`Energy/EDF/2026`), always, even for a single instance. The entity folder is never dated; only its year subfolder carries the period. Crucially, **documents from different entities are different series and never share a folder** — run 6 wrongly pulled an Enercoop bill into `Energy/EDF`; the grouping prompt now forbids grouping across issuers and only joins files of the SAME entity AND year. The `<ENTITY>/<YEAR>` rule (and its example) is carried consistently across the analysis, organize and grouping prompts (replacing the old neutral `Factures-electricite/2026` example), and also resolves the long-pending CV year-subfolder question (`…/CV/2026`). Prompt-only; the run invariant and deepen-only locks are unchanged.

  **(No redundant date in the stem):** the AI occasionally leaked a date into the name (`…__2025-08_Degats-eaux-cuisine.jpg`) although the `YYYY-MM-DD_HH-mm-ss__` prefix already carries the date. `naming.sanitize_filename_stem` now deterministically strips a **month-precision** date (`YYYY-MM` / `YYYY-MM-DD`) that LEADS the stem; a bare year is kept (it can be part of the identity, e.g. `Recensement-population_2026`). `build_timestamped_filename` routes through the same sanitizer, so the guard is model-independent and applies to fallback filenames too. The prompt rule "never put a date in the name" stays as the first line of defense.

  **(Consistent meter-reading names):** run 6 produced `Releve_Compteur-eau` and `Releve_eau_Compteur` for two readings of the same kind. The analysis few-shot gains a meter template — `relevé de compteur → Releve_<resource>` (e.g. `Releve_eau`, `Releve_electricite`), the resource measured rather than the word "compteur" — so two readings of the same resource get the same name.

  **(Name a new file to its series — 3a):** when grouping places a new singleton into a series subfolder that already holds files of the same kind, it may now return a `name` — the new file's stem rewritten to match its siblings' structure — applied via a new `override_name` on `pipeline._file_cataloged` (and recorded in the fiche). Only fires when grouping DEEPENS a branch; no already-filed file is renamed (that heavier harmonization, which would touch the symlink/catalog/mirror machinery, is intentionally out of scope). `GroupingResult` gains an optional `name` field.

  `tests/test_naming.py` +3 (leading-date strip / bare-year kept / timestamped filename), `tests/test_ai_analysis.py` (entity-year structure + meter few-shot), `tests/test_ai_grouping.py` +3 (entity naming, cross-entity ban, consistent-name field + parsing), `tests/test_ai_organize.py` (entity-year assertions), `tests/test_organize_pipeline.py` +1 (grouping name renames the new file). 273 tests green.

- **Local models (Ollama) can now READ images and scanned PDFs, and the test suite is offline by default.** Two reading paths that were Mistral-only gain an `ollama` provider branch so a local model can do the work for free: `read_with_vision` → `call_ollama_vision` (image sent to Ollama `/api/chat` as base64), and `read_with_ocr` → `call_ollama_ocr` (a scanned PDF is rendered page-by-page to PNG with **PyMuPDF**, then read by a vision model). The model is chosen purely by the chain (`PROCRAFILER_AI_IMAGE_*` / `_OCR_*` = `ollama:<model>`), so it is trivial to swap. Verified live: `qwen2.5vl:7b` (vision) and `minicpm-v` (OCR) transcribed a document perfectly; `gemma4:12b` classifies text well. `call_ollama_chat` now sends `format:"json"` and lifts Ollama's 2048-token default context (`options.num_ctx`, env `PROCRAFILER_OLLAMA_NUM_CTX`, default 8192) — without it, long analysis prompts were silently truncated to empty output. A new **`PROCRAFILER_AI_THROTTLE`** (seconds, default 0) inserts a pause before each real provider call, to avoid overheating a GPU on long local runs (Mistral/production unaffected). **Tests:** the routine suite is now offline and deterministic by default — `tests/__init__.py` points `PROCRAFILER_ENV_FILE` at an empty fixture so a real `.env` (Mistral key/chains) is never loaded, and a new `Makefile` provides `make test` (offline) and `make test-ollama` (opt-in real local integration, skipped unless `PROCRAFILER_OLLAMA_IT=1`); the offline guard runs only when `tests` is imported as a package, so discovery must use `-t . -s tests` (documented in the README). New deps: **PyMuPDF**. New `tests/test_ollama_integration.py`; `tests/test_ai_reader.py` +7 (mocked Ollama vision/OCR), `tests/test_ai_providers.py` +4 (throttle).

- **`Personal/Administrative/Energy` joins the base library tree.** Energy bills (electricity, gas) are a document kind virtually every household has — same universal status as `Telecom`, which has been in the base since the taxonomy redesign. The third real sandbox run showed two electricity bills (different issuers) landing bare in `Housing` with nothing to group them; a dedicated base folder gives them a stable, predictable home (and the series rule can still create finer subfolders under it, e.g. per issuer). `taxonomy.BASE_LIBRARY_DIRECTORIES` +1; README and `docs/spec-mvp-v1.md` §10 base trees updated; `tests/test_config_layout.py` asserts the folder is created.

- **Root singletons now detect existing series folders and regroup related files together (Plan D — M1, M2, M3).** Three interlocking changes fix the "two compteur d'eau filed apart" regression that plan B's folder-sets didn't cover, because root singletons skip the organizer:

  **(M1 — analysis prompt):** The `category_path` rule in `_build_analysis_prompt` gains a **SERIES RULE**: for an obviously recurring kind (meter reading, bank statement, payslip, bill, tax notice, insurance policy…), propose a series subfolder even for a single instance (e.g. `.../Housing/Releves-eau`) — and REUSE that exact folder from the live tree when one already fits. In practice, the first *compteur d'eau* now creates `Housing/Releves-eau` on its own; the second one finds it in the tree and routes itself there — often without ever needing M2. `tests/test_ai_analysis.py` +1 (`test_prompt_has_series_folder_rule`).

  **(M2 — ai_grouping module):** After `_route_from_analysis` confirms a route for each root singleton, a new lightweight **`propose_grouping(document, candidate_branches)`** step (new module `src/procrafiler/ai_grouping.py`) checks whether the new file should share a common series folder with existing files. It receives the **names of existing files** along the 1–3 candidate destination branches (up to 30 filenames, newest first, depth ≤ 2 from the branch root), and returns `{"path": "…", "group_with": […]}`. High bar: only regroup what is OBVIOUSLY the same recurring series. Reuses the ANALYSIS chain (`PROCRAFILER_AI_ANALYSIS_*`) — no new env var. Free skip (no AI call) when no candidate branch has existing files on disk. New `tests/test_ai_grouping.py` (12 tests: fallback on empty dict / all-empty branches / no chain, full JSON parsing, null-path, invalid JSON, API error, prompt contains filenames, prompt has date-at-START rule and HIGH BAR, prompt includes document name/summary).

  **(M3 — regroup existing file):** When `group_with` names existing files, each is **moved** to the common series folder, a **relative symlink is left at its old location** pointing to the new path, the catalog entry (`current_path`, `current_filename`, `content_json.category_path`) and the mirror copy are updated, and a `regrouped` counter is added to the run summary. Guard rails: only `LIBRARY_STORED` files inside `library_root`; unknown-on-disk names → warning-only, no crash; symlink failure (FS without support) → log + continue; never moves `DECISION_PENDING` files. Action-log events: `library_file_regrouped`, `symlink_left` (or `symlink_failed`), `mirror_regrouped`. Symlinks are never mirrored (they are positional markers, not documents). `tests/test_organize_pipeline.py` +2 (two singletons regrouped into a series — second run moves first file and leaves symlink at old path, catalog updated; unknown filename in `group_with` → warning without crash, new file still filed). `tests/test_batch_cli.py`: `_files_under` updated to exclude symlinks from the real-document count (they are markers, not documents). 243 tests green.

- **Files of the same kind are now named with a CONSISTENT structure.** The analysis prompt's `name` instruction gains a generalist skeleton + few-shot examples per common kind — CV → `CV-Nom-Prenom` (+ role), bill → `Facture-<issuer>`, bank statement → `Releve-<bank>`, certificate/diploma → `<Type>-<organisme>-<subject>` — so two documents of the same kind get the same name structure (fixing the two CVs that came out as `CV-Simon-LOUVEL-2026` vs `Simon-LOUVEL-CV-Developpeur-web`). New rules: **never put a date in the name** (the `YYYY-MM-DD_HH-mm-ss__` prefix already carries it — the timestamp is always first, never duplicated or moved to the end), do not repeat words already implied by the entity (`Facture-EDF`, not `Facture-EDF-electricite`), and use the **user-context identity** for the person's name (e.g. a CV → that exact `Nom-Prenom`). Prompt-only change; the entity-first rule and JSON parsing are unchanged. `tests/test_ai_analysis.py` +1 (the prompt carries the per-kind templates and the no-date rule). 228 tests green.

- **Optional user-context file feeds the AI to disambiguate classification and naming.** A free-text file describing the user (passions, work, places, identity) is now loaded and injected into BOTH the per-file analysis prompt and the set-organizer prompt, as a non-authoritative *"About the user"* block (the document content still rules). It resolves the hobby-vs-professional ambiguity (e.g. a music mixing desk → `Hobbies` reliably, not at random) and anchors identity for naming. It is **read-only, never written to the action log, never committed**. Lookup order: `PROCRAFILER_CONTEXT_FILE` (explicit path) → `./context.txt` then `./context.md` (working dir, where the template lives) → `<PROCRAFILER_CONFIG_HOME>/context.{txt,md}`; absent or empty → behavior unchanged. Template guidance (`# …` lines and `<!-- … -->`) is stripped so only real notes reach the model; content is capped at 2000 chars. Ships `context.example.txt` / `context.example.md` (plain text recommended — equally legible to the model, more robust for non-technical users); the real `context.txt`/`.md` is gitignored. New `procrafiler.user_context.load_user_context`; `analyze_content(…, user_context=…)` and `organize_set(…, user_context=…)`; the pipeline loads it during a run. New `tests/test_user_context.py` (8: lookup order, env override, config-home fallback, comment stripping, empty→None, length cap), prompt-injection tests in `test_ai_analysis.py` (+2) and `test_ai_organize.py` (+2/-block), and an end-to-end test in `test_organize_pipeline.py` (+1: the context reaches the analysis prompt). 227 tests green.

- **The organizer now keeps a dropped folder TOGETHER by default (Plan B hardened — R1–R5).** The run already organized each subfolder as a set (PR #34), but the organizer's prompt was too permissive, so a single water-damage claim still scattered across `Housing` + `Insurance` and several date-variant folders. The prompt now enforces: (R1) put the WHOLE set into ONE destination folder by default; (R3) never spread one affair across two base categories; (R4) one affair name + one period, with the **date at the START** of the folder name (`…/Insurance/2025-08_Degats-eaux-Annoville`, never at the end); (R2) only place a file elsewhere if its content is **FLAGRANTLY** a different case (high bar — a nuance like "damage photo vs insurance form of the same affair" is NOT a split); (R5) image descriptions come from a vision model that **can hallucinate** → never disperse the set on a single shaky photo, and trust the drop-folder grouping more for image-heavy sets. Scale guard (R7): a folder larger than `pipeline.ORGANIZE_MAX_SET` (80) is organized in **batches** instead of one giant call (normal folders stay in a single call). Spec + checklist: `docs/plan-b.md`. `tests/test_ai_organize.py` +2 (the prompt encodes R1–R5; no hypothesis block without a drop-folder), `tests/test_organize_pipeline.py` +1 (a large folder is organized in batches). 215 tests green. *(Mechanism unchanged — still catalog-the-folder-then-organize-the-whole-set, one folder at a time; this only tightens the organizer's judgment so a coherent set isn't dispersed.)*

- **`run` now processes each Inbox subfolder as a coherent SET — catalogue the whole folder first, then organize it as a whole — so a set is placed together instead of scattering (chantier 3b, the real two-phase rework).** `process-all` no longer files each file the instant it's read. It works in two phases per top-level Inbox subfolder (the **set** boundary): **(1) CATALOG** — read + analyze every file of the folder into its fiche (staged in `Queue`, nothing filed yet); **(2) ORGANIZE** — send the whole set's fiches to `organize_set` (Mistral medium) in **one** call, which places each file, creating shared **dated affair/series folders** (e.g. a whole water-damage claim → `…/Insurance/Degats-eaux-2025-08/`). Because the organizer sees the entire set at once, **uncertain files no longer leak to the decisions queue one by one** — the set's coherence decides them (the key failure of the earlier per-file approach, where ~half a claim folder scattered across categories + Manual_Review). The drop-folder is treated as a **strong-but-overridable hypothesis** ("privilégier, pas imposer"): the organizer assumes the files probably belong together under the folder's theme, but each file's content has the last word — an off-topic file is split out. Files loose in the Inbox **root** are singletons (per-file route, not grouped). With no `PROCRAFILER_AI_ORGANIZE_*` chain configured there is no organize phase (each file keeps its per-file category), so behavior is unchanged by default. **Internals:** the 530-line ingest monolith was split into reusable phases — `pipeline._catalog_one_inbox_file` / `_read_and_analyze` / `_route_from_analysis` (now accepts a set-level `organized_path` that overrides the per-file guess) / `_file_cataloged`; `process-all` orchestrates catalogue→organize→file with per-file resilience and intra-run dedup. Replaces and removes the earlier incremental post-pass (`_organize_ingested` + `_move_mirror_copy`). `organize_set`'s prompt now centers on the source-folder hypothesis and receives each doc's `original_filename`. New `tests/test_organize_pipeline.py` (8): set grouped into the dated affair folder, catalog + mirror follow, **uncertain files don't leak (the set decides)**, the organizer is called **once** over the whole set with the folder hypothesis in the prompt, an off-topic file is split out, root singletons are not organized as a set, and no-chain means no grouping.

- **Set-aware organization brain (`ai_organize`) — the foundation for grouping documents into dated affair/series folders (chantier 3a).** Where the per-file analysis decides one document at a time (and so scatters a coherent set — the real run dumped a whole water-damage claim flat into `Insurance/`), `organize_set(documents, …)` looks at a *whole set* of already-analyzed fiches together and proposes a final folder for each, creating shared, dated, named subfolders for the affair/event/series they belong to. Two **generalist** rules in the prompt (never per-type hardcoding): group documents of the same affair/event/series into one dated named folder; and create a series folder even from a single instance when the document is of an obviously recurring kind (meter reading, statement, payslip, bill, tax notice…). New `ORGANIZE` AI task (its own chain `PROCRAFILER_AI_ORGANIZE_*`, defaulting to `mistral-medium-latest` — the broader view warrants a stronger model); with no chain or on failure each document falls back to its per-file category (no grouping), and a document the model omits keeps its own proposed path. The caller validates every proposed path against the taxonomy. ### Changed

- `procrafiler feature-set actions_log|catalog_snapshot|mirror_sync` now actually toggles runtime behavior. Previously the flags were stored in `settings.json` and displayed by `procrafiler status` but never consulted by the pipeline — turning a flag off was a silent no-op.
  - `actions_log` off → no JSON lines written to `actions_log.jsonl`.
  - `catalog_snapshot` off → `catalog_snapshot.json` is no longer rewritten on each operation.
  - `mirror_sync` off → no mirror copy is performed; a single `mirror_sync_skipped` event is logged (when `actions_log` is on).
- `cmd_purge_mirror_trash` in the CLI now honors `actions_log` when emitting its summary event, matching pipeline behavior.
- `process_next_inbox_file` walks the 14-state flow machine explicitly. Before the audit the spec listed 14 states but the pipeline never visited any of them — it jumped straight from "file detected" to a final string. Every checkpoint now calls `validate_transition`, raising loudly if a future change tries an illegal jump.
- CLI commands `process-once`, `process-all`, and `purge-mirror-trash` acquire a runtime lock before touching state. Read-only commands (`status`, `features`, `policy-effective`, `feature-set`, `init-layout`) stay lock-free.
- `process_all_inbox_files` no longer re-reads the entire `actions_log.jsonl` before and after every file just to count mirror failures (an O(N²) scan that grew with the log). It now reads the per-file `mirror_failed` flag returned by the pipeline and tallies inline. The public `process_next_inbox_file` keeps its string return contract unchanged.
- **Documentation: corrected the routing/classification logic** in `README.md` (Goals + new "Routing and Classification" section, formerly "Deterministic Routing") and `docs/spec-mvp-v1.md` (§9 IA Architecture Policy, §10 routing baseline). The previous wording prescribed extension→category routing ("common extensions are auto-routed to standard branches"), which conflates a technical signal (extension) with a semantic decision (category). The corrected logic states that the extension is a **technical dispatch signal only** (it selects which AI capability reads the file) and that the **destination category is always decided by AI from the file content**, never from the extension.
- **Decoupled technical dispatch from semantic classification in the code.** `taxonomy.decide_route_for_filename` (extension→category folder) is replaced by `taxonomy.dispatch_for_filename`, which returns a `DispatchDecision(media_type, reason, matched_extension)` — `media_type` is the reader class (pdf/text/office/image/video/audio/archive), never a destination. Since no AI classifier exists yet, every readable (known-extension) file is now ingested into an interim review directory (`taxonomy.INTERIM_LIBRARY_DIR` = `Revue_Manuelle`) instead of a wrongly extension-derived category like `Personnel/Documents`. Files with no/unknown extension still go to manual review in the queue (they can't even be read). The naming + mirror + catalog steps are unchanged; only the destination changed. When AI classification lands, it will replace the interim destination with a real content-derived category.

### Fixed

- **A network timeout on one file no longer crashes the whole batch.** During a real run, a slow Mistral vision call raised a socket `TimeoutError` that escaped uncaught and aborted `process-all` partway through (a traceback, with the remaining files unsorted). Two layers of robustness: (1) **root cause** — `_post_json` now converts any OS-level network failure (socket `TimeoutError`, connection reset, `URLError`…) into a retryable `ProviderCallError`, so the readers' existing retry + failover handles it gracefully and the file falls back to manual review instead of crashing; (2) **defense in depth** — `process_all_inbox_files` now wraps each file so any unexpected per-file exception is logged (`process_error`), counted, and skipped, and the batch continues (with a safety bound against an unlikely stuck-file loop). Re-running is safe (processed files are deduplicated). New `tests/test_batch_resilience.py` (4): a socket timeout / connection reset becomes a `ProviderCallError`; a failing file doesn't abort the batch and is logged.

- **Empty Inbox subfolders are now cleaned up after their files are processed.** When files are dropped inside subfolders (e.g. `Inbox/CV/…`), processing moves them out and used to leave the empty folders behind as clutter. The pipeline now prunes them (bottom-up, so nested empties go too) at the end of `process-all` and after `process-once`. Strict bounds keep this safe: the Inbox drop point itself is never removed, symlinked directories are never followed or `rmdir`-ed (a symlink pointing outside the Inbox can't drag the cleanup elsewhere), and only genuinely-empty real directories are removed — a folder still holding an unprocessed file is left untouched. New `pipeline._prune_empty_inbox_dirs`; `tests/test_inbox_prune.py` (6) covering bottom-up removal, root-never-removed, keep-dir-with-file, partially-empty trees, the symlink-escape guard, and the `process-all` integration.
- `tests/test_doctor.py` now clears any `PROCRAFILER_AI_*` chain and `MISTRAL_API_KEY` in `setUp`, so its AI-config assertions are deterministic even when another test has loaded the repo `.env` into the process environment (the CLI auto-loads `cwd/.env`). Each doctor test still sets the specific chain/key it needs.
- `tests/test_cli.py::test_purge_mirror_trash_cli` no longer drifts: it pins `PROCRAFILER_FAKE_NOW` so the CLI uses the same reference timestamp the test fabricates `mtime`s relative to. Previously the test silently broke as the real-world clock moved past the test's hand-crafted 2026-04-02 reference.

### Security

- `.gitignore` now blocks `*.env` runtime files (with `!.env.example` to keep the template tracked), `*.key`/`*.pem` private keys, and the KDE `.directory` desktop artifact.
- `scripts/install.sh` creates `procrafiler.env` and `install-meta.env` under a `0077` umask and re-enforces `0600` (user mode) or `0640` (system mode) on every install run, including upgrades from versions that did not protect the files. Closes a path where a shared system could expose `MISTRAL_API_KEY` to any local user.
- `scripts/update.sh` no longer `source`s `install-meta.env` as shell. The previous behavior allowed any tampered metadata file to execute arbitrary commands, including as root in system mode. Metadata is now parsed key-by-key with a dedicated reader that only extracts known keys (`REPO_ROOT`, `VENV_DIR`).
