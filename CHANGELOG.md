## [Unreleased]

### Added

- **`Personal/Administrative/Energy` joins the base library tree.** Energy bills (electricity, gas) are a document kind virtually every household has — same universal status as `Telecom`, which has been in the base since the taxonomy redesign. The third real sandbox run showed two electricity bills (different issuers) landing bare in `Housing` with nothing to group them; a dedicated base folder gives them a stable, predictable home (and the series rule can still create finer subfolders under it, e.g. per issuer). `taxonomy.BASE_LIBRARY_DIRECTORIES` +1; README and `docs/spec-mvp-v1.md` §10 base trees updated; `tests/test_config_layout.py` asserts the folder is created.

- **Root singletons now detect existing series folders and regroup related files together (Plan D — M1, M2, M3).** Three interlocking changes fix the "two compteur d'eau filed apart" regression that plan B's folder-sets didn't cover, because root singletons skip the organizer:

  **(M1 — analysis prompt):** The `category_path` rule in `_build_analysis_prompt` gains a **SERIES RULE**: for an obviously recurring kind (meter reading, bank statement, payslip, bill, tax notice, insurance policy…), propose a series subfolder even for a single instance (e.g. `.../Housing/Releves-eau`) — and REUSE that exact folder from the live tree when one already fits. In practice, the first *compteur d'eau* now creates `Housing/Releves-eau` on its own; the second one finds it in the tree and routes itself there — often without ever needing M2. `tests/test_ai_analysis.py` +1 (`test_prompt_has_series_folder_rule`).

  **(M2 — ai_grouping module):** After `_route_from_analysis` confirms a route for each root singleton, a new lightweight **`propose_grouping(document, candidate_branches)`** step (new module `src/procrafiler/ai_grouping.py`) checks whether the new file should share a common series folder with existing files. It receives the **names of existing files** along the 1–3 candidate destination branches (up to 30 filenames, newest first, depth ≤ 2 from the branch root), and returns `{"path": "…", "group_with": […]}`. High bar: only regroup what is OBVIOUSLY the same recurring series. Reuses the ANALYSIS chain (`PROCRAFILER_AI_ANALYSIS_*`) — no new env var. Free skip (no AI call) when no candidate branch has existing files on disk. New `tests/test_ai_grouping.py` (12 tests: fallback on empty dict / all-empty branches / no chain, full JSON parsing, null-path, invalid JSON, API error, prompt contains filenames, prompt has date-at-START rule and HIGH BAR, prompt includes document name/summary).

  **(M3 — regroup existing file):** When `group_with` names existing files, each is **moved** to the common series folder, a **relative symlink is left at its old location** pointing to the new path, the catalog entry (`current_path`, `current_filename`, `content_json.category_path`) and the mirror copy are updated, and a `regrouped` counter is added to the run summary. Guard rails: only `LIBRARY_STORED` files inside `library_root`; unknown-on-disk names → warning-only, no crash; symlink failure (FS without support) → log + continue; never moves `DECISION_PENDING` files. Action-log events: `library_file_regrouped`, `symlink_left` (or `symlink_failed`), `mirror_regrouped`. Symlinks are never mirrored (they are positional markers, not documents). `tests/test_organize_pipeline.py` +2 (two singletons regrouped into a series — second run moves first file and leaves symlink at old path, catalog updated; unknown filename in `group_with` → warning without crash, new file still filed). `tests/test_batch_cli.py`: `_files_under` updated to exclude symlinks from the real-document count (they are markers, not documents). 243 tests green.

- **Files of the same kind are now named with a CONSISTENT structure.** The analysis prompt's `name` instruction gains a generalist skeleton + few-shot examples per common kind — CV → `CV-Nom-Prenom` (+ role), bill → `Facture-<issuer>`, bank statement → `Releve-<bank>`, certificate/diploma → `<Type>-<organisme>-<subject>` — so two documents of the same kind get the same name structure (fixing the two CVs that came out as `CV-Simon-LOUVEL-2026` vs `Simon-LOUVEL-CV-Developpeur-web`). New rules: **never put a date in the name** (the `YYYY-MM-DD_HH-mm-ss__` prefix already carries it — the timestamp is always first, never duplicated or moved to the end), do not repeat words already implied by the entity (`Facture-EDF`, not `Facture-EDF-electricite`), and use the **user-context identity** for the person's name (e.g. a CV → that exact `Nom-Prenom`). Prompt-only change; the entity-first rule and JSON parsing are unchanged. `tests/test_ai_analysis.py` +1 (the prompt carries the per-kind templates and the no-date rule). 228 tests green.

- **Optional user-context file feeds the AI to disambiguate classification and naming.** A free-text file describing the user (passions, work, places, identity) is now loaded and injected into BOTH the per-file analysis prompt and the set-organizer prompt, as a non-authoritative *"About the user"* block (the document content still rules). It resolves the hobby-vs-professional ambiguity (e.g. a music mixing desk → `Hobbies` reliably, not at random) and anchors identity for naming. It is **read-only, never written to the action log, never committed**. Lookup order: `PROCRAFILER_CONTEXT_FILE` (explicit path) → `./context.txt` then `./context.md` (working dir, where the template lives) → `<PROCRAFILER_CONFIG_HOME>/context.{txt,md}`; absent or empty → behavior unchanged. Template guidance (`# …` lines and `<!-- … -->`) is stripped so only real notes reach the model; content is capped at 2000 chars. Ships `context.example.txt` / `context.example.md` (plain text recommended — equally legible to the model, more robust for non-technical users); the real `context.txt`/`.md` is gitignored. New `procrafiler.user_context.load_user_context`; `analyze_content(…, user_context=…)` and `organize_set(…, user_context=…)`; the pipeline loads it during a run. New `tests/test_user_context.py` (8: lookup order, env override, config-home fallback, comment stripping, empty→None, length cap), prompt-injection tests in `test_ai_analysis.py` (+2) and `test_ai_organize.py` (+2/-block), and an end-to-end test in `test_organize_pipeline.py` (+1: the context reaches the analysis prompt). 227 tests green.

- **The organizer now keeps a dropped folder TOGETHER by default (Plan B hardened — R1–R5).** The run already organized each subfolder as a set (PR #34), but the organizer's prompt was too permissive, so a single water-damage claim still scattered across `Housing` + `Insurance` and several date-variant folders. The prompt now enforces: (R1) put the WHOLE set into ONE destination folder by default; (R3) never spread one affair across two base categories; (R4) one affair name + one period, with the **date at the START** of the folder name (`…/Insurance/2025-08_Degats-eaux-Annoville`, never at the end); (R2) only place a file elsewhere if its content is **FLAGRANTLY** a different case (high bar — a nuance like "damage photo vs insurance form of the same affair" is NOT a split); (R5) image descriptions come from a vision model that **can hallucinate** → never disperse the set on a single shaky photo, and trust the drop-folder grouping more for image-heavy sets. Scale guard (R7): a folder larger than `pipeline.ORGANIZE_MAX_SET` (80) is organized in **batches** instead of one giant call (normal folders stay in a single call). Spec + checklist: `docs/plan-b.md`. `tests/test_ai_organize.py` +2 (the prompt encodes R1–R5; no hypothesis block without a drop-folder), `tests/test_organize_pipeline.py` +1 (a large folder is organized in batches). 215 tests green. *(Mechanism unchanged — still catalog-the-folder-then-organize-the-whole-set, one folder at a time; this only tightens the organizer's judgment so a coherent set isn't dispersed.)*

- **`run` now processes each Inbox subfolder as a coherent SET — catalogue the whole folder first, then organize it as a whole — so a set is placed together instead of scattering (chantier 3b, the real two-phase rework).** `process-all` no longer files each file the instant it's read. It works in two phases per top-level Inbox subfolder (the **set** boundary): **(1) CATALOG** — read + analyze every file of the folder into its fiche (staged in `Queue`, nothing filed yet); **(2) ORGANIZE** — send the whole set's fiches to `organize_set` (Mistral medium) in **one** call, which places each file, creating shared **dated affair/series folders** (e.g. a whole water-damage claim → `…/Insurance/Degats-eaux-2025-08/`). Because the organizer sees the entire set at once, **uncertain files no longer leak to the decisions queue one by one** — the set's coherence decides them (the key failure of the earlier per-file approach, where ~half a claim folder scattered across categories + Manual_Review). The drop-folder is treated as a **strong-but-overridable hypothesis** ("privilégier, pas imposer"): the organizer assumes the files probably belong together under the folder's theme, but each file's content has the last word — an off-topic file is split out. Files loose in the Inbox **root** are singletons (per-file route, not grouped). With no `PROCRAFILER_AI_ORGANIZE_*` chain configured there is no organize phase (each file keeps its per-file category), so behavior is unchanged by default. **Internals:** the 530-line ingest monolith was split into reusable phases — `pipeline._catalog_one_inbox_file` / `_read_and_analyze` / `_route_from_analysis` (now accepts a set-level `organized_path` that overrides the per-file guess) / `_file_cataloged`; `process-all` orchestrates catalogue→organize→file with per-file resilience and intra-run dedup. Replaces and removes the earlier incremental post-pass (`_organize_ingested` + `_move_mirror_copy`). `organize_set`'s prompt now centers on the source-folder hypothesis and receives each doc's `original_filename`. New `tests/test_organize_pipeline.py` (8): set grouped into the dated affair folder, catalog + mirror follow, **uncertain files don't leak (the set decides)**, the organizer is called **once** over the whole set with the folder hypothesis in the prompt, an off-topic file is split out, root singletons are not organized as a set, and no-chain means no grouping.

- **Set-aware organization brain (`ai_organize`) — the foundation for grouping documents into dated affair/series folders (chantier 3a).** Where the per-file analysis decides one document at a time (and so scatters a coherent set — the real run dumped a whole water-damage claim flat into `Insurance/`), `organize_set(documents, …)` looks at a *whole set* of already-analyzed fiches together and proposes a final folder for each, creating shared, dated, named subfolders for the affair/event/series they belong to. Two **generalist** rules in the prompt (never per-type hardcoding): group documents of the same affair/event/series into one dated named folder; and create a series folder even from a single instance when the document is of an obviously recurring kind (meter reading, statement, payslip, bill, tax notice…). New `ORGANIZE` AI task (its own chain `PROCRAFILER_AI_ORGANIZE_*`, defaulting to `mistral-medium-latest` — the broader view warrants a stronger model); with no chain or on failure each document falls back to its per-file category (no grouping), and a document the model omits keeps its own proposed path. The caller validates every proposed path against the taxonomy. New `tests/test_ai_organize.py` (8). **This is the isolated brain; wiring it into `run` (process a folder as a set) is the next step (3b) and is where the behavior changes.**

- **Photos are now dated by their EXIF capture date, and every file records the Inbox subfolder it came from.** Two grouping/dating signals added to the fiche, in preparation for the set-aware *organize* phase. (1) **EXIF**: the filename date cascade now starts with the photo's EXIF `DateTimeOriginal` for images (before the AI content date, mtime, then processing time) — hard metadata that sidesteps the vision model hallucinating a date off the image, and that makes photos taken the same day group naturally. Adds **Pillow** as a dependency; `pipeline._exif_capture_datetime`, and `_resolve_document_date(..., media_type=…)`. (2) **Origin folder**: the fiche gains `source_folder` (the Inbox subfolder the file was dropped in — e.g. `Water-Damage`; null at the root) and `effective_date` (the resolved filing date). Files dropped together in a folder are a candidate set for the future organize pass — a hint, not ground truth. New `tests/test_exif_and_origin.py` (4) and `tests/test_document_date.py` +7 (EXIF read, EXIF beats AI-date/mtime for images, EXIF ignored for non-images, no-EXIF fallback). `docs/spec-mvp-v1.md §4.1` updated.

- **The catalog now remembers what each document *is* — a per-document fiche (summary, keywords, entities) read once and kept, so files become searchable and reorganizable without ever re-reading them.** This closes a long-standing gap between intent and implementation: the catalog held only filesystem metadata (path, status, hash), and the text read from each file was used for naming/classification then **thrown away**. Now a `content_json` column (spec §4.1) stores a structured fiche per document — `name`, `document_date`, `category_path` (+ `alternatives`), `summary`, `keywords`, extensible `entities` (issuer, doc_type, amounts, references…), `language`, and provenance (`read_via`, `provider`, `model`, `analyzed_at`). It is keyed to the stable `doc_id`, so it survives renames and moves (and the future `reorganize`). The human-readable `catalog_snapshot.json` inlines the fiche as **nested** JSON (the DB keeps it as a queryable string). `review` resolutions and `library-trash` preserve the fiche (and `review` updates its `category_path` to the user's choice). New `catalog.content_json` column + `upsert_document(content_json=…)`; `pipeline._write_catalog_snapshot` inlines it. Tests: `tests/test_classification_pipeline.py` +1 (fiche persisted in catalog **and** nested in the snapshot, no raw blob leaking), `tests/test_review.py` +1 (resolution keeps the fiche and updates its category), `tests/test_catalog.py` (migration coverage).

- **One unified AI *analysis* call replaces the separate naming and classification passes (read once, decide everything).** A single call now reads the already-extracted text and returns the whole fiche at once — name, date, category (+ alternatives), summary, keywords, entities — so the searchable metadata **rides along** at no extra AI call or cost (the date already worked this way; now everything does). New `procrafiler.ai_analysis.analyze_content` → `AnalysisResult`; the old `ai_naming.suggest_stem_with_ai` and the whole `ai_classification` module are **removed**, their shared HTTP/chain/JSON plumbing kept in `ai_naming` (now a task-agnostic provider module). A valid JSON reply is a success even when `category_path` is null (the metadata is still captured; routing — file / decisions queue / manual review — is decided by the pipeline as before). **Breaking (pre-release, never deployed):** the per-task env chains `PROCRAFILER_AI_NAMING_*` and `PROCRAFILER_AI_CLASSIFICATION_*` are replaced by a single `PROCRAFILER_AI_ANALYSIS_*` (primary/fallback/timeout/retries); `doctor` now reports `task_analysis`. Default model stays `mistral-small-latest`. New `tests/test_ai_analysis.py` (9) and `tests/test_ai_providers.py` (4); the pipeline/OCR/vision/progress/doctor/document-date tests were repointed from the two old tasks to the unified one.

- **Decisions queue + `procrafiler review` — the AI defers to you when it's unsure, instead of guessing or silently dumping to manual review (Point 2b).** Classification returns a confident `path` *or* a set of `alternatives`; when it has no confident path but does offer plausible options, the file is **parked** in `Revue_Manuelle` with catalog status `DECISION_PENDING`, carrying the AI's options (validated against the taxonomy), the reason, and a content snippet. Parked files are deliberately **not mirrored** — the placement isn't settled yet. `procrafiler review` walks the queue interactively: for each file it shows the options and you pick a number, **type a custom path** (a new subfolder, or a **brand-new root category** — the one place new roots are allowed, never the AI), or skip. On resolution the file is re-filed out of `Revue_Manuelle`, the catalog entry becomes `LIBRARY_STORED` with its pending flag cleared, and only now is it mirrored. `process-all` reports a `pending_decisions` count and points you to `review`; `run` / `process-*` still never touch already-filed files. When the AI offers no usable option (unconfigured, hard failure, or all options invalid) the file is plain manual review as before — settled and mirrored, not stuck pending. New `catalog.pending_decision` column + `list_pending_decisions()`; `taxonomy.normalize_review_path` (allows a new root, snaps typed input onto an existing base case-insensitively); `pipeline.run_review` / `resolve_pending_decision` (injectable I/O for testing); `ClassificationResult.alternatives`. Tests: `tests/test_review.py` (16) — review-path normalization, parking vs. plain manual review vs. confident placement (incl. the no-mirror-while-pending invariant), and the resolve loop (pick an option, custom new root, skip-keeps-pending, invalid label / missing source raise); `tests/test_ai_classification.py` +4 (alternatives carried, null-path-with-options is *uncertain not failure* and isn't retried, null-path-no-options retries then falls back); `tests/test_catalog.py` +1 (`list_pending_decisions` filters and clears); `tests/test_cli.py` +2 (`review` with nothing pending, and resolving via stdin).

- **AI classification now builds a folder tree, not just a flat category (Point 2a).** The classifier returns a *path* (e.g. `Administratif/Impots`) instead of one flat category. The AI is shown the **existing tree** and told to **reuse** a folder if one fits, otherwise **create a subfolder under an existing base category** — it may never invent a new top-level category. The proposed path is validated by `taxonomy.normalize_category_path`: it must start with an existing base category, new subfolder names are slugified (so `Impôts` / `impots` / `Impôts 2026` collapse to one folder), and total depth is capped by `policy.toml`'s `taxonomy.max_depth` (default raised 6 → **10**, a safety net, not a design constraint). New subfolders are materialized lazily. On doubt the AI returns just the base category (flat); a path with no valid base, or genuine uncertainty, still routes to manual review. `run` stays stable — it never touches already-filed files (deliberate reorganization will be a separate `reorganize` command). New `taxonomy.existing_category_paths` / `normalize_category_path`; `ai_classification.classify_content` now takes `base_categories` + `existing_paths` and returns a `path`.
- Tests: `tests/test_subfolders.py` (13) — path normalization (flat base, subfolder, name normalization, multi-segment base, unknown base rejected, depth cap, uncapped), existing-tree listing, and pipeline integration (creates a subfolder, flat base when the AI returns the base only, unknown base → manual review, reuses an existing subfolder). `tests/test_ai_classification.py` rewritten for the path contract.

- **Real-time progress during `process-once` / `process-all`.** The pipeline now streams a human-readable line per step as each file is handled — the file being processed (with its Inbox-relative subpath), what was read (`read: text, N chars` / `OCR: …` / `vision: …`), the classification outcome (`classified → Banque` or `→ manual review (reason)`), folder creation, duplicates, and the final placement (`filed → Category/2026-04-30_…__name.ext`). So you can watch the run and interrupt it (Ctrl-C; the runtime lock releases cleanly). Implemented as an optional `progress` callback threaded through `process_all_inbox_files` / `process_next_inbox_file` (type `pipeline.ProgressFn`); the pipeline never prints directly — the CLI passes a flushing printer. New `tests/test_progress.py` (3): progress lines for a manual-review file, for an AI-classified file (`classified → Banque`, `filed → Banque/…`), and that omitting the callback is safe.

- **Files are dated by their content, not by when they're processed.** The stored filename's `YYYY-MM-DD_HH-mm-ss__` prefix now follows a cascade: (1) the date the AI finds inside the document (a letter/invoice/statement date) — the naming model now returns `{"stem": "...", "date": "YYYY-MM-DD"|null}`, set at **midnight UTC** so same-day documents group together instead of scattering by processing seconds; (2) else the file's modification time; (3) else the processing time. Only the filename prefix uses this date — action-log and catalog timestamps keep the real processing time. No extra API call (the date rides along in the existing naming response). New `ai_naming._extract_document_date` + `AINameSuggestion.document_date`, and `pipeline._resolve_document_date`. New `tests/test_document_date.py` (10): date extraction (valid / null / missing / bad format / impossible), the resolution cascade (AI date → midnight, mtime fallback, invalid-AI-date fallback, missing-file → now), and an end-to-end test that a document stating "30 April 2026" is filed as `2026-04-30_00-00-00__…`.

- **The Inbox is now read recursively** — files dropped inside subfolders (any depth) are processed too, not just files at the Inbox root. The original folder structure is irrelevant (the AI re-classifies each file). A strict boundary guard keeps the scan inside the Inbox: `os.walk(followlinks=False)` does not descend into symlinked directories, and any file whose resolved path escapes the Inbox (e.g. a symlink pointing elsewhere on disk) is skipped. New `pipeline._iter_inbox_files`. New `tests/test_inbox_recursion.py` (4): a nested file is processed, deep nesting works, a symlinked file pointing outside the Inbox is ignored, and a symlinked directory escaping the Inbox is not descended.
- **`docs/backlog.md`** — a running checklist of deferred work and open questions. Seeded with the first observed classification ambiguity (a manual for professional-grade equipment used as a hobby, classified `Professionnel` where `Personnel` was expected — the Perso/Pro split depends on the user's relationship to the document, not its content; cases are logged generically/anonymized), three candidate solutions to weigh once more cases are collected, and the known deferred features (SUPERVISOR, VIDEO/audio, automatic watcher) and open evaluations (live OCR/vision smoke test, `mistral-small` on images).

- **Docs and config refreshed for the completed IA-first core.** `README.md`: removed the now-false "naming is a filename placeholder" note (naming derives from content since the naming change); rewrote "Project Status" to describe the implemented reading/naming/classification/safety behavior; added a "Commands" section documenting `process-once` / `process-all` (+ `--dry-run`), `doctor`, `reconcile-snapshot`, `library-trash`, and `purge-mirror-trash`. `.env.example`: per-task chains now show the recommended models (NAMING/CLASSIFICATION → `mistral-small-latest`, OCR → `mistral-ocr-latest`, IMAGE → `mistral-medium-latest`) and clearly mark which tasks are USED vs reserved (PDF readable is read locally; SUPERVISOR and VIDEO/audio are not implemented yet); notes that real env files are gitignored. `.gitignore`: added `sandbox/` for the local dev test area.
- **Safety re-verified (no code change):** the app never deletes inbox/library files — duplicates and library removals are *moved* to dedicated trash folders for manual deletion; the only `unlink`/`rmdir` is in `purge-mirror-trash`, scoped to old superseded backups in `Mirror_Trash`, TTL-based, and only on explicit invocation. All other filesystem ops are moves/copies within app-managed roots.

- **AI vision reader for images (`procrafiler.ai_reader.read_with_vision`)** — the last core reader, completing the read→name→classify chain for every file type. When `content_reader` flags an image (`reader_hint="vision"`), the pipeline sends it to a Mistral vision model (`call_mistral_vision`, chat completions with the image inlined as a base64 `data:image/<mime>` URI) asking it to transcribe + describe the content; the returned text then feeds classification and content-based naming. A photographed receipt can now be read, named, and filed in `Administratif`/`Banque`. The chain is read from `PROCRAFILER_AI_IMAGE_PRIMARY` / `_FALLBACK` (never hardcoded), with retry + failover and a 90s default timeout. No chain / all-failed / empty result → fall back to manual review (`Revue_Manuelle`); the pipeline logs `vision_read_success` or `vision_read_unavailable`. `tests/test_ai_reader.py` grows vision coverage (image MIME mapping, the chat-vision payload shape, missing-key/HTTP errors, chain fallback/success/empty); `tests/test_ocr_pipeline.py` gains two pipeline tests (an image is vision-read then classified into a real category, and routed to `Revue_Manuelle` when no vision chain is configured).

- **AI OCR reader for scanned PDFs (`procrafiler.ai_reader`)** — extends the reading chain to files we can't read on disk. When `content_reader` flags a PDF as scanned (`reader_hint="ocr"`), the pipeline now sends it to Mistral OCR (`POST /v1/ocr`, the file inlined as a base64 `data:application/pdf` URI) and concatenates the per-page markdown into text. That text then feeds the existing classification and content-based naming, so a scanned bank statement can finally land in `Banque` with a content-derived name. `read_with_ocr(path)` reads its chain from `PROCRAFILER_AI_OCR_PRIMARY` / `_FALLBACK` (never hardcoded), with retry + failover and a longer default timeout (120s). No chain, all-providers-failed, or empty OCR → fall back to manual review (`Revue_Manuelle`); the pipeline logs `ocr_read_success` or `ocr_read_unavailable`. New `tests/test_ai_reader.py` (11) covering the OCR text extraction, the `/v1/ocr` payload shape (data-URI), missing-key/HTTP/rate-limit errors, and the chain fallback/failover/retry behavior; `tests/test_ocr_pipeline.py` (2) proving a scanned PDF is OCR-read then classified into a real category, and routed to `Revue_Manuelle` when no OCR chain is configured.

- **AI classification from content (`procrafiler.ai_classification`)** — the first AI step that actually decides a destination category, and the first time files reach real categories (`Banque`, `Administratif`, …) instead of always landing in `Revue_Manuelle`. `classify_content(text, allowed_categories=…)` sends the locally-extracted text to the configured AI and expects JSON `{"category": "<one of the allowed>"}`. The provider/model is never hardcoded: the chain is read from `PROCRAFILER_AI_CLASSIFICATION_PRIMARY` / `_FALLBACK` (same mechanism as naming), with retry + failover. Guardrails per spec §7/§9: an unconfigured chain, a provider failure, an uncertain answer (`{"category": null}`), or a category outside the allowed list all fall back to manual review (`Revue_Manuelle`) — the AI never forces a guessed destination. Document text sent to the model is capped (`MAX_CONTENT_CHARS`). New `taxonomy` helpers `classifiable_categories()` / `category_label()` / `category_from_label()` expose the allowed categories (every base directory except the interim review bucket).
- Pipeline now classifies every locally-readable file (text + readable PDF) from its content and routes it to the AI-chosen category; scans/images (awaiting their OCR/vision readers) and uncertain/unconfigured outcomes still go to `Revue_Manuelle`. Emits `classification_success` or `classification_manual_review` events. With no chain configured the behavior is unchanged (everything → `Revue_Manuelle`), so this is backward-compatible by default.
- Tests: `tests/test_ai_classification.py` (8, Mistral mocked) covering no-chain fallback, valid category, out-of-list rejection, explicit-null uncertainty, failover, retries+backoff, noisy-JSON parsing; `tests/test_classification_pipeline.py` (3) proving a text file lands in the real category when the AI is confident, and in `Revue_Manuelle` when unconfigured or uncertain.

### Changed

- **The original filename and the drop-folder name are now kept and fed to the analysis as hints.** A real run misread a CV (`CV_Simon-LOUVEL_…`) as an "employment contract example" and a folder of water-damage photos scattered across categories — because the analysis was blind to two strong signals. The IA-first "never trust the filename" softens to **"use it as an indicator, not ground truth"**: the fiche now keeps `original_filename`, and `analyze_content` receives the original filename + the source folder as **hints** in the prompt (explicitly framed as non-authoritative — the content stays decisive, the hints only disambiguate). A file named `CV …` is recognized as a CV; a photo in a `Water-Damage` folder leans toward the claim. Generalist, no per-type rules. `tests/test_ai_analysis.py` +2 (prompt carries/omits the hints), `tests/test_exif_and_origin.py` +1 (`original_filename` kept in the fiche). *(This is step 1; the bigger fix — analyzing a whole folder as a coherent set so nothing scatters — is the per-folder rework that follows.)*

- **Files are now named by their most distinctive entity, not by their type/format.** A real run produced useless names like `Document-texte-OpenDocument` and `Profil-professionnel` for a CV. The analysis prompt's `name` instruction is reworked into a **generalist** rule (no per-type hardcoding, which would multiply into conflicting rules): name a document by what specifically identifies it — its key **entity** (person, organization, subject) plus the key detail — and *never* by its file type or format (with empty words like "document"/"fichier"/"texte" explicitly discouraged). A CV thus naturally keeps the person's name, a bill the issuer, etc. Only the prompt changes; parsing is unchanged. New `tests/test_ai_analysis.py` test asserting the prompt embeds the entity-first rule. `docs/spec-mvp-v1.md §4.1` updated.

- **The base library taxonomy is redesigned: English, organized by life *context* then *subject* — never by file format.** The old French, partly format-based tree (`Personnel/Documents`, `Banque`, `Personnel/Medias/Images|Videos|Audio`, `Revue_Manuelle`…) is replaced by a shallow, context-first tree: top level is `Personal` / `Work` / `Manual_Review`; admin is **nested inside each context** (resolving the Administrative-vs-Personal overlap and the awkward naming it caused); the **format buckets are gone** (a sinistre photo → its subject like any document, a holiday photo → its event folder). Few top-level entries + a clear binary at each level make it navigable for screen-reader / ADHD users and legible for the AI; cross-cutting views ("all my bills") are left to the catalog fiche (keywords/entities) + soft-links rather than duplicated folders. Full base tree: `Personal/{Administrative/{Identity,Taxes,Banking,Insurance,Health,Housing,Telecom,Vehicle},Education,Hobbies}`, `Work/{Employment/{Administrative,Payslips},Business/{Administrative,Invoices,Expenses,Clients}}`, `Manual_Review`. The AI still creates anything finer itself (`Clients/<name>`, `Insurance/Water-Damage-2025`, `Personal/Trip-Spain-2025`). `taxonomy.INTERIM_LIBRARY_DIR` is now `Manual_Review`; `existing_category_paths` is de-duplicated (the tree is nested). **Breaking (pre-release):** existing libraries with old French folders are not auto-migrated. Tests repointed to the new categories; `README` + `docs/spec-mvp-v1.md §10` + `docs/backlog.md` updated. The taxonomy is hardcoded for now — making it user-editable is a planned follow-up.

- **AI naming now derives the filename from the document CONTENT, not the original filename.** `suggest_stem_with_ai(content, *, fallback_stem=…)` prompts the model with the extracted text (capped at `MAX_NAMING_CONTENT_CHARS`) and asks for a descriptive title. The original filename is no longer the basis for naming — it survives only as `fallback_stem`, the deterministic last resort used when the AI can't run (no chain configured, no readable content, or all providers fail). The pipeline passes the reader's extracted text; files with no readable content yet (scans/images awaiting OCR/vision) use the filename fallback and a new `no_content` reason. Closes the "naming was a filename placeholder" gap flagged when the IA-first principle was documented (#12). `test_ai_naming.py` updated to the new signature, plus two new tests: naming uses the content (and not the filename stem) in the prompt, and an empty content returns the `no_content` fallback without calling the AI.

- **Local content extraction (`procrafiler.content_reader`)** — the first step of the IA-first reading chain, with no AI call and no network. `extract_text_content(path, media_type)` returns a `ContentExtraction` that either carries locally-readable text or a `reader_hint` telling the future AI layer which model is needed: text files are read directly; PDFs are inspected with `pypdf` for a usable text layer (readable → text extracted; scanned/no text layer → `reader_hint="ocr"`); images → `reader_hint="vision"`; unreadable/corrupt PDFs fall back to OCR. The pipeline now reads every dispatchable file before storing it and logs a `content_read` event (media type, char count, whether an AI reader is still needed). Routing is unchanged for now (files still land in `Revue_Manuelle` until AI classification exists). Adds `pypdf` (pure-Python, no system libs → broad Linux compatibility) as the first runtime dependency. New `tests/test_content_reader.py` (8 tests) covering text / readable PDF / scanned PDF / sub-threshold / corrupt PDF / image / unsupported types.

- **Documentation: anchored the project's problem and its "IA-first" principle.** `README.md` now opens with the problem it solves (files pile up with meaningless names; manual sorting is procrastinated until unmanageable) followed by a "How it works (IA-first)" section; `docs/spec-mvp-v1.md` gains §1.0 Problem, §1.1 Operating principle, and §1.2 Action boundary. The founding premise is now unambiguous: every file is processed without exception (including already-named ones, since a name may be wrong); the existing filename is never a trusted input; an AI reads the content and derives BOTH the new name AND the category from that reading; the extension is only a technical dispatch signal. The **action boundary** is stated explicitly: the app only ever acts on files in its drop folder (`Inbox`, the "vrac") and never touches anything else on disk except folders it created. Also aligned: README Goals, "Routing and Classification" and "AI Naming" sections, and spec §3 naming example (`__Original-Name.ext` → an AI-derived name like `2026-04-01_22-10-06__Releve-BNP-Avril-2026.pdf`) and §9 (naming derives from content; content-reading is the prerequisite for naming + classification).

### Changed

- `procrafiler feature-set actions_log|catalog_snapshot|mirror_sync` now actually toggles runtime behavior. Previously the flags were stored in `settings.json` and displayed by `procrafiler status` but never consulted by the pipeline — turning a flag off was a silent no-op.
  - `actions_log` off → no JSON lines written to `actions_log.jsonl`.
  - `catalog_snapshot` off → `catalog_snapshot.json` is no longer rewritten on each operation.
  - `mirror_sync` off → no mirror copy is performed; a single `mirror_sync_skipped` event is logged (when `actions_log` is on).
- `cmd_purge_mirror_trash` in the CLI now honors `actions_log` when emitting its summary event, matching pipeline behavior.
- `process_next_inbox_file` walks the 14-state flow machine explicitly. Before the audit the spec listed 14 states but the pipeline never visited any of them — it jumped straight from "file detected" to a final string. Every checkpoint now calls `validate_transition`, raising loudly if a future change tries an illegal jump.
- CLI commands `process-once`, `process-all`, and `purge-mirror-trash` acquire a runtime lock before touching state. Read-only commands (`status`, `features`, `policy-effective`, `feature-set`, `init-layout`) stay lock-free.
- `process_all_inbox_files` no longer re-reads the entire `actions_log.jsonl` before and after every file just to count mirror failures (an O(N²) scan that grew with the log). It now reads the per-file `mirror_failed` flag returned by the pipeline and tallies inline. The public `process_next_inbox_file` keeps its string return contract unchanged.
- **Documentation: corrected the routing/classification logic** in `README.md` (Goals + new "Routing and Classification" section, formerly "Deterministic Routing") and `docs/spec-mvp-v1.md` (§9 IA Architecture Policy, §10 routing baseline). The previous wording prescribed extension→category routing ("common extensions are auto-routed to standard branches"), which conflates a technical signal (extension) with a semantic decision (category). The corrected logic states that the extension is a **technical dispatch signal only** (it selects which AI capability reads the file) and that the **destination category is always decided by AI from the file content**, never from the extension.
- **Decoupled technical dispatch from semantic classification in the code.** `taxonomy.decide_route_for_filename` (extension→category folder) is replaced by `taxonomy.dispatch_for_filename`, which returns a `DispatchDecision(media_type, reason, matched_extension)` — `media_type` is the reader class (pdf/text/office/image/video/audio/archive), never a destination. Since no AI classifier exists yet, every readable (known-extension) file is now ingested into an interim review directory (`taxonomy.INTERIM_LIBRARY_DIR` = `Revue_Manuelle`) instead of a wrongly extension-derived category like `Personnel/Documents`. Files with no/unknown extension still go to manual review in the queue (they can't even be read). The naming + mirror + catalog steps are unchanged; only the destination changed. When AI classification lands, it will replace the interim destination with a real content-derived category.

### Fixed

- **A network timeout on one file no longer crashes the whole batch.** During a real run, a slow Mistral vision call raised a socket `TimeoutError` that escaped uncaught and aborted `process-all` partway through (a traceback, with the remaining files unsorted). Two layers of robustness: (1) **root cause** — `_post_json` now converts any OS-level network failure (socket `TimeoutError`, connection reset, `URLError`…) into a retryable `ProviderCallError`, so the readers' existing retry + failover handles it gracefully and the file falls back to manual review instead of crashing; (2) **defense in depth** — `process_all_inbox_files` now wraps each file so any unexpected per-file exception is logged (`process_error`), counted, and skipped, and the batch continues (with a safety bound against an unlikely stuck-file loop). Re-running is safe (processed files are deduplicated). New `tests/test_batch_resilience.py` (4): a socket timeout / connection reset becomes a `ProviderCallError`; a failing file doesn't abort the batch and is logged.

- **Empty Inbox subfolders are now cleaned up after their files are processed.** When files are dropped inside subfolders (e.g. `Inbox/CV/…`), processing moves them out and used to leave the empty folders behind as clutter. The pipeline now prunes them (bottom-up, so nested empties go too) at the end of `process-all` and after `process-once`. Strict bounds keep this safe: the Inbox drop point itself is never removed, symlinked directories are never followed or `rmdir`-ed (a symlink pointing outside the Inbox can't drag the cleanup elsewhere), and only genuinely-empty real directories are removed — a folder still holding an unprocessed file is left untouched. New `pipeline._prune_empty_inbox_dirs`; `tests/test_inbox_prune.py` (6) covering bottom-up removal, root-never-removed, keep-dir-with-file, partially-empty trees, the symlink-escape guard, and the `process-all` integration.
- `tests/test_doctor.py` now clears any `PROCRAFILER_AI_*` chain and `MISTRAL_API_KEY` in `setUp`, so its AI-config assertions are deterministic even when another test has loaded the repo `.env` into the process environment (the CLI auto-loads `cwd/.env`). Each doctor test still sets the specific chain/key it needs.
- `tests/test_cli.py::test_purge_mirror_trash_cli` no longer drifts: it pins `PROCRAFILER_FAKE_NOW` so the CLI uses the same reference timestamp the test fabricates `mtime`s relative to. Previously the test silently broke as the real-world clock moved past the test's hand-crafted 2026-04-02 reference.

### Security

- `.gitignore` now blocks `*.env` runtime files (with `!.env.example` to keep the template tracked), `*.key`/`*.pem` private keys, and the KDE `.directory` desktop artifact.
- `scripts/install.sh` creates `procrafiler.env` and `install-meta.env` under a `0077` umask and re-enforces `0600` (user mode) or `0640` (system mode) on every install run, including upgrades from versions that did not protect the files. Closes a path where a shared system could expose `MISTRAL_API_KEY` to any local user.
- `scripts/update.sh` no longer `source`s `install-meta.env` as shell. The previous behavior allowed any tampered metadata file to execute arbitrary commands, including as root in system mode. Metadata is now parsed key-by-key with a dedicated reader that only extracts known keys (`REPO_ROOT`, `VENV_DIR`).
